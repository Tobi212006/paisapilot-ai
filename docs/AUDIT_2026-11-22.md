## C. Security review and limits

Inspected owner-scoped query boundaries, bound SQL, validation, demo cookies, platform/Supabase identity adapters, CSRF/CORS constraints, no-store headers, CSP, quotas, export/deletion and provider consent boundaries. Existing tests exercise isolation, amounts/dates, atomic import/replay, refund/transfer calculations, goal bounds and safe provider failures. No real financial data was used.

Targeted scans covered the original GitHub history (40 commits, 137 unique blobs) and managed source (3 commits, 62 blobs) for Google API-key, GitHub-token and private-key patterns. No matches. These patterns are not a complete secret or PII scan, do not cover external chats/settings/logs and do not establish revocation of a known earlier exposure. Do not label the credential issue resolved. [SECURITY](SECURITY.md) gives safe rotation steps without exposing a key.

The review uses OWASP-style authentication, object authorization, input, data protection and availability boundaries; it does not claim ASVS certification or full OWASP coverage. Gateway header stripping, real two-account sign-in/recovery, backup restore, retention and independent review remain open. Local quotas are process-local. No real-money execution, bank access or new feature modules were added.
