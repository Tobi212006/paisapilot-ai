# Contributing

1. Create a branch named `feat/<short-name>` or `fix/<short-name>`.
2. Keep modules small and test changed business logic.
3. Never commit secrets, real bank data, personal information or credentials.
4. Update README status and CHANGELOG when behaviour changes.
5. Run backend tests and frontend production build before opening a PR.
6. Describe limitations honestly; do not label heuristics as trained AI/ML or synthetic data as live data.
